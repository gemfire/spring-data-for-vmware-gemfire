## Question

What does "done" look like for this effort? Is the destination a written spec, a decision, or an in-place code change — and if a spec, what shape (single doc vs. multiple, what audience)?

## Answer

The destination is **two written documents**, produced by this effort with no production code changes:

1. A full **technical design spec** — interfaces, module boundaries, migration plan — sized for implementation handoff.
2. A shorter **companion rationale / executive-summary doc** for stakeholder review and sign-off.

This map plans and specifies; it does not implement. No ticket on this map resolves into code — that work happens after the spec is handed off.
