# Region callbacks: implementation and native evidence

For [Complete region events, listeners and writers](../../wayfinder-issues/17-complete-region-events-listeners-and-writers.md), against GemFire **10.4.0-build.3056.df98c835**. This implements the callback foundation; it does not claim that Spring Data is native-free or that every operation reachable through an event's region/cache handle is complete.

## Contracts and ownership

- `DriverCacheListener` declares all nine native entry/region callbacks. `DriverCacheWriter` declares all five before-event callbacks. Their adapters deliberately opt into no-op methods; the native adapters implement every native method explicitly. The existing destruction-only `DriverRegionLifecycleListener` remains a separate resolver contract.
- `DriverRegionMembershipListener` and `DriverRegionRoleListener` include initial members, remote create/departure/crash and role gain/loss. The role adapter also inherits the membership adapter, matching the native adapter hierarchy. Native registration preserves the implemented specializations.
- `DriverDeclarable.init(Properties)` and `initialize(DriverConnection, Properties)` are separate hooks, with native default no-op semantics. Loader, writer and listener adapters forward both. Programmatic registration does not initialize callbacks implicitly. Declarative assembly invokes hooks explicitly using injected callback instances, properties and a borrowed connection; automatic Spring factory/XML adoption remains in the assembly and region-factory tickets.
- `RegionCallbacks` installs peer callbacks before creation and client listeners before creation, so applications can observe region-create. The native client factory has no loader/writer creation setters: those options fail with `NOT_INTRODUCED` / `ClientRegion.creationLoaderWriter`, before creating the region. Post-creation loader/writer setters remain supported. No application class-name loading or global registration is added.
- Region listener add/remove/reinitialization/lookup and writer replacement/lookup preserve application instance identity across region handles. Loader lookup completes access to the existing loader registration. Event-producing operations add callback-argument put, entry invalidate/destroy and region invalidate/destroy. Entry destroy returns the native previous value. Other region overloads, inherited Map semantics and attributes remain in the region operations/configuration tickets.
- Reinitialization treats null/empty lists as removal, preserves native list order and duplicates and closes old general registrations, including retained instances. Resolver lifecycle registrations remain installed and their delegate cleanup runs only when the region/cache lifetime ends. This adds no atomicity or callback synchronization guarantee.

## Payloads and failures

Typed cache, entry, region, role and timestamped-entry views preserve callback arguments/availability, origin, operation, region, member, old/new values, old-value availability, client origin, transaction identity, serialized values and timestamps. Views are lazy and callback-scoped: they do not eagerly deserialize, retain native events or extend off-heap lifetimes. Serialized forms retain native null/availability behavior; no alternate serialization format is introduced.

`DriverOperation` covers all 50 public native operation constants, predicates, corresponding create/update conversions, numeric codes and display names. Native tests compare every constant and boolean predicate. Ordinal checks cover all byte values, including native reserved null slots 50–54 and invalid indices.

Member and transaction wrappers preserve native equality/ordering and identity metadata. These are foundations for the distributed-system and transaction tickets, not replacements for their remaining runtime and externalization contracts. Durable member metadata is a typed immutable value; mutation of native durable attributes remains a distributed-services obligation. Timestamped events have native payload fixtures; actual WAN conflict-resolver delivery remains in the WAN/queue ticket.

Writer failures veto before mutation. Both typed unsupported reasons and typed driver failures retain their identity across native writer wrapping; arbitrary application runtime failures become `WRITER_VETO`, with a safe outer message and original cause. Loader failures retain their established classification. Listener failures use the common mapper and then follow native dispatch suppression; they do not veto an already-completed mutation. Event accessor failures also use the common mapper. `DriverOperationException.getRootCause()` provides the inherited callback-exception diagnostic operation, including safe termination for cyclic cause chains. Original causes remain trusted diagnostics and may contain native messages.

Native callback cleanup catches/logs runtime failures, as observed in `AbstractRegion.closeCacheCallback`; adapters do not override that engine policy. The mock retains its established fail-fast loader/writer cleanup policy and still releases all callbacks/regions before surfacing a failure. This is a documented mock distinction, not a new common shutdown guarantee. Listener cleanup failures are suppressed in both drivers. Errors are not converted to runtime failures.

## Native details discovered by behavioral tests

1. Late membership registration is exposed by `RegionAttributes` as the package-private `WrappedRegionMembershipListener` until native initialization. The 10.4 driver recognizes precisely that class and calls its `getWrappedListener` accessor reflectively for identity/lookup. No wrapper or native object escapes through the SPI. Native duplicate registration and removal use the same application identity. This exact-version internal dependency must be reverified for another driver release.
2. `RoleEvent.getRequiredRoles()` declares `Set<String>`, but a real 10.4 role event carries native `Role` objects. The event adapter converts those to role names, also accepting strings from compliant implementations. A real peer join/leave test catches this discrepancy; a signature-only or proxy-only test would miss it.
3. A real `afterRegionLive` callback requires the subscription marker. The fixture uses a durable client, subscription-enabled pool, durable interest and `readyForEvents`; it verifies operation `MARKER`. The local mock emits no synthetic live event.
4. Locators cannot host application regions in this native release. Network fixtures use separate locator, peer and client/server processes, ephemeral ports, readiness/event acknowledgments, bounded waits and process cleanup. They do not claim separate native caches within one JVM are isolated.

## Validation evidence

- Shared `RegionCallbackContract`: all locally meaningful entry/region callbacks and payloads, creation-time registration, writer veto for create/update/destroy/clear/region-destroy with both unsupported reasons, callback identity/removal/replacement/duplicates, resolver cleanup protection, listener suppression, loader events and explicit initialization. The default-method contract now probes all 42 defaults, including the declarable hooks.
- `NativeCallbackCoverageTests`: all native callback methods, including inherited and specialized hooks, through registered adapters; all operation constants/predicates/ordinals; lazy serialized/timestamped payloads, availability and accessor failures; real transaction identity; both registered writer/loader initialization hooks. The registered-adapter fixture is explicitly a seam test, not synthetic proof of network delivery.
- `NativeDistributedCallbackTests`: actual peer join, graceful region departure, process crash, role gain/loss, remote entry values and native serialization, plus the durable client's live marker. Callback-thread assertions are captured and surfaced on the test thread.
- Mock-specific rejection test: distributed listener registration and region creation fail explicitly without leaving a registration or region behind. The mock does not fabricate remote members, transactions, serialized bytes or subscription events.
- Full driver checks, both scoped Spring runtimes and full Spring Data main/unit/integration plus Spring Test main/unit source compilation are recorded in the owning ticket. Whole-module boundary verification remains green against existing debt; it is not strict native-free compliance.

## Coverage accounting and follow-ups

The frozen inventory remains **3,851 rows / 292 native types**. All **291 callback-owned rows** now have implementation evidence: **145 implemented leaf/value rows** and **146 partial rows**. Partial rows retain explicit reachable-contract or adoption obligations: complete region handles/configuration, full cache assembly, distributed member services, transaction externalization and WAN delivery. The complete inventory has **3,369 missing / 337 partial / 145 implemented** rows. No frozen requirements are removed.

Spring signature/import/source counts remain **588 / 144 / 624**; production/unit/integration native file counts remain **182 / 122 / 128**. Callback SPI implementation does not remove a legacy Spring consumer by itself. Spring's composable listeners/writers, annotations, XML and factory entry points migrate together in Region factory and configuration migration. The full callback interfaces and no-op adapter classes now provide that ticket's typed target.
